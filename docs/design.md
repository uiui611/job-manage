# 設計と制約

## 対象

自分が登録した信頼するスクリプトを、断続的に起動するデスクトップ・計算用マシンで実行する単一利用者向け基盤です。マルチテナント・悪意のあるコードの隔離・サーバーの高可用性は対象外です。

ワーカーは Linux Docker と Windows ネイティブに対応します。Windows では環境側で提供した Node/Python を Windows Sandbox またはホストで直接実行します。OS 共通の制御プロトコル・実行契約と、Linux プロセスグループ / Windows Job Object による停止処理を分離しています。Windows の GPU 利用は実際のドライバ・実行環境ごとに確認します。

## データと状態

DB が定義・実行要求・状態・ログ・ファイル参照・トークンハッシュの正本です。JOB 投入時に定義と入力を Run に固定します。手動再実行では元の Run を復活させず、同じ定義・入力を持つ新しい Run を作ります。

初期版は Run ごとに1回の実行です。内部の `attempt_id` と接続ごとの `session_id` で、前の接続から届いた遅延結果を拒否します。自動再試行用の複数 Attempt 履歴はありません。

サーバーは単一稼働です。再起動時に `assigned` / `running` を `failed` にし、待機列を保持します。ワーカーが切断を認識すると子プロセスの停止を試みますが、切断直後に停止できる保証や、完了済み外部書き込みの取り消しはありません。サーバーが成功を確定できなかった場合は失敗として扱います。

DB に接続できない間は状態の保存自体もできないため、切断後の失敗記録が DB 復旧後になる場合があります。状態保存は再試行しますが、JOB 本体を自動で再実行するものではありません。

## スケジューリング

実行可能なドライバと必須タグを照合し、空いていて有効なワーカーに古い待機 JOB を割り当てます。GPU の性能測定・空き VRAM の観測・優先度・リソース予約はありません。タグは管理上の宣言です。

GPU を共有する複数のワーカーを同時起動すると、各ワーカーの「1実行枠」を超えて GPU 全体の競合が発生します。初期版では同じ GPU を使うワーカーを1個にする運用が適しています。

## 認証

- API トークン: クラスタ内の他アプリケーションから利用。利用者別の詳細権限はありません。
- ワーカートークン: ワーカー接続だけに利用。
- プロキシ共有トークン: 認証済みの前段プロキシが `X-Job-Proxy-Token` を上書きして付与。
- 署名付き URL: 対象ファイルの短期間の転送権限。

管理画面のログイン処理を前段に委ねても、バックエンドへ直接届いた認証のない API リクエストは拒否します。ブラウザー向け更新要求にはカスタムヘッダーを要求し、他サイトからの単純なフォーム送信を防ぎます。プロキシ自体の認証設定・Cookie 方針も必要です。

## 実行と隔離

ワーカーは JOB ごとに Node/Python の子プロセスを起動します。Linux は既存コンテナ、Windows はホスト・Sandbox 内で実行します。タイムアウト・キャンセル・切断時には子孫プロセスを停止します。Windows はランタイムを suspended で起動し、JOB の Job Object に登録してから再開します。ワーカー自身も外側の Job Object に入れることで、登録途中を含む強制終了時の子プロセス残留を防ぎます。Job Object の設定に失敗した場合は実行しません。

JOB の環境変数にはワーカートークンを渡しません。ただし、同じコンテナ内の任意コード実行はワーカー本体との強いセキュリティ境界ではありません。信頼できないコードへの対応が必要になった場合は、JOB ごとの VM / コンテナと短寿命の実行資格情報を別途設計します。

CPU・メモリ・PID 数の上限は外側の Docker / Kubernetes で設定します。作業ディレクトリがディスクを使い切るリスクを抑えるには、容量が制限されたボリュームを使ってください。Kubernetes の `emptyDir.sizeLimit` は超過後に eviction が起こり得るため、厳密なファイルシステムクォータと同じではありません。

## 今後の範囲

- 実機の AMD / NVIDIA GPU を使った派生イメージと実行試験
- Windows Sandbox と実機 GPU を組み合わせた実行試験
- 定義・履歴・未使用ファイルの保持期限と削除機能
- 調停可能なサーバー複数稼働とローリング更新
- より大きいファイル、マルチパート転送、転送再開
- GPU ごとの排他制御、ジョブ依存関係、予約実行

これらは初期版で実装・検証済みとは扱いません。
